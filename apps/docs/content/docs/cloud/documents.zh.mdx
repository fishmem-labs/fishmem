文档不是会话记忆。Documents 保存长篇来源并提供检索上下文；Memory 保存简洁持久结论。

## 两种写入路径

| 路径 | 适用内容 | 权威来源 |
| --- | --- | --- |
| 直接文本 | 服务端已经拥有的 Markdown、笔记或文本 | 提交的准确 UTF-8 内容 |
| 文件上传 | PDF、Office、OpenDocument、EPUB、邮件、图片与结构化文本 | 不可变上传字节 |

直接文本通过 `documents.ingest` 同步建立不可变版本、当前来源指针与确定性分块。文件使用三步生命周期：创建上传、上传准确字节、完成上传；随后持久任务调用 Docling，保留原始文件、Markdown 与无损 JSON 结构，再通过同一 `DocumentCorpus` 写入。

```text
创建来源 -> 上传字节 -> 完成并校验 -> 排队提取
        -> Docling -> 保留产物 -> 提交文档版本 -> 建立投影
```

## 搜索与引用

`documents.search` 按项目、来源与可选元数据过滤，返回命中分块、UTF-8 字节区间、版本、来源标识与可选相邻证据。应用应在提示词中把文档证据与用户记忆分区，并保留引用字段用于回答展示与审计。

## 删除

删除稳定来源会永久移除所有版本、分块、向量、直接文本原件、上传文件与提取产物。它不同于删除单条记忆 tombstone。删除前先导出或确认保留策略，并等待持久删除操作完成。
