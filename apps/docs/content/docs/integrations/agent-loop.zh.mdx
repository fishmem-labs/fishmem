---
title: 集成契约
description: 在任何智能体框架中正确安排召回与持久写入。
---

每种框架集成都应保留同一条循环：

```text
认证 -> 推导作用域 -> 召回 -> 组装提示词 -> 执行
     -> 验证结果 -> 写入持久结论 -> 保留回执
```

## 在相关决策前召回

用当前任务或用户消息搜索，不要使用无关的泛化查询。把记忆放在有明确标签的提示词区块中；若之后需要反馈或排障，请保留结果 ID。

## 在证据成立后写入

不要把拟执行的工具动作保存成已完成结果。应在事务成功或用户更正成为权威事实后写入，并从应用事件生成确定性的幂等键。

## 分开不同资源

- 最近对话留在框架短期状态；
- 持久结论使用 Memory；
- 手册与长来源使用 Documents；
- 异步推理写入保留 Event 回执。

## 不把授权交给模型

从已认证的服务端请求推导项目凭据与结构化作用域。绝不能让模型输出选择另一租户的 `user_id` 或 API Key。即使框架自带 checkpoint，也应遵循这套契约：执行检查点与持久语义记忆解决的是不同问题。
